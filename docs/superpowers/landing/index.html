Speculative-token flow under PP the path we change

Last rank samples + runs the rejection oracle, broadcasts the grid; non-last ranks rebuild their next input. This is the bug-prone seam (bricks 40 / 80).

The rejection oracle is the correctness gate. Greedy: a draft token is accepted iff it equals target_logits.argmax(-1), else replaced by it → output is a pure function of (target argmax, draft) → weight-agnostic. So dummy/MiMo weights validate the cascade shape; only acceptance-rate needs real weights. rejection_sampler.py:708 :452 target_argmax
